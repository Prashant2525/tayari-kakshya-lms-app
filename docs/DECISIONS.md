Source of answers: `OPEN_QUESTIONS.md` (owner answers, 2026-10-02) + follow-up clarifications the same day.

**Principle adopted from the answers ("manage from admin portal"):** wherever the owner chose admin control, the rule is
implemented as **validated configuration data in PostgreSQL, editable in the Admin CMS**, with no hard-coded business
values. Development seed data uses clearly fake placeholder values; real values are entered by the owner before launch
(tracked in `LAUNCH_CONFIG_CHECKLIST` section of `PROJECT_STATE.md`).

| T-046 | Certificates | **Templates** (`certificate_templates`, permission `certificates:manage`) hold the wording (issuer, title, line before the name, line before the course — en/ne), up to 3 signatories, the printed language and the **share of lessons** (1–100 %, D-049); a course picks one (`courses.certificate_template_id`, from the course's Certificate tab, `courses:edit` or `certificates:manage`, staff scopes apply). **Issuing** (D-050): a student with **active access to the course** whose template is active, once finished ÷ live lessons ≥ the share (an empty course never), gets one certificate per course (unique student + course) — checked when a lesson is finished and whenever My certificates or the course page is opened, so templates added later and lessons finished earlier count.
